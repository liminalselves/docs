# 创作角色

进入「智能体 → 创作」可以创建自己的角色。这篇指引从「想清楚」讲到「发布」，逐个字段说明怎么写、为什么这么写。

## 下笔之前：先把角色想清楚

动笔前用三句话回答三个问题，比直接填表更容易写出立得住的角色：

1. **TA 是谁？**——身份、处境、和你（用户）的关系。比如「深夜电台的主持人，正在直播，听众就是用户」。
2. **TA 想要什么？**——目标和动机决定对话走向。主持人想做好这期节目，就会主动找话题。
3. **TA 不会做什么？**——底线和边界。比如「不会泄露其他听众的隐私」。

这三句话之后会分别落进人设的不同字段。想清楚再写，后面返工会少很多。

## 一个容易搞混的点：简介给人看，人设给模型看

- **简介**只有一句话的位置，出现在广场卡片上。它的任务是让刷广场的人 3 秒内决定要不要点进来——写卖点和适合人群，比如「嘴上嫌弃你、实际替你操心的毒舌室友｜适合日常吐槽」。
- **人设**才是模型每轮都会读到的内容，决定角色实际怎么表现。把约束行为的话全写进简介，模型根本看不到，这是新手最常见的错误。

## 基本信息

![基本信息](/images/agent-create-basic.webp)

- **名称**：角色的名字。
- **简介**：见上，只用于广场和列表展示。
- **头像**：角色的形象。
- **参考图片**：最多 4 张（每张 ≤5MiB）。这是给[生图](/guide/agent/chat#生图)用的「默认形象照」——选择支持参考图的生图模型时，这些图会作为形象依据传过去，让插图的脸和衣服更稳定。想被画得准，就选角度清晰、服装完整、光线干净的图。
- **公开提示词**：决定别人能否查看你的完整角色设定。公开能积累口碑，谨慎则保护创意，按需选择。

## 人设：模型的「角色说明书」

![人设](/images/agent-create-persona.webp)

四个字段各管一件事：

| 字段 | 管什么 | 写什么 |
| ---- | ------ | ------ |
| 性格与行为 | TA 是什么样的人 | 性格特点、重视什么、遇事如何反应和判断 |
| 背景设定 | TA 从哪来 | 经历、世界观位置、重要关系、长期目标 |
| 说话方式 | TA 怎么开口 | 语气、称呼、句长、口癖、是否用比喻、是否主动追问 |
| 禁止行为 | TA 绝不做什么 | 安全边界，如不剧透、不越界承诺、不脱离设定 |

写的时候记住一条：**模型认具体，不认形容词**。对比一下：

- 含糊：「她很温柔。」——模型只能泛泛地客气。
- 具体：「她说话轻但语速快，习惯在对方说完后先复述一遍对方的意思再回应；被人道谢时会不好意思地转移话题。」——模型有动作可模仿，表现立刻具体。

禁止行为同理：写「不会主动提起用户的现实隐私」比「要守规矩」有效得多。规则短而明确，一条一个点，比长篇大论更容易被遵守。

## 对话与示例

![对话与示例](/images/agent-create-dialogue.webp)

**开场白**：会话创建时自动出现的第一条消息。适合交代场景和角色当前状态（「深夜电台刚过 12 点，主持人切了一首歌……」），也等于给用户示范了「这个角色会怎样开启话题」。留空则没有开场白。别把大量设定塞进开场白——设定该去人设和世界书。

**示例对话**：以「用户 / 助手」逐条添加的范例（最多 24 条）。它们会标注为「仅供参考」进入系统提示，模型从中学习语气和节奏，但不会当作真实聊天记录。

写示例的建议：

- 挑**典型场景**，而不是日常闲聊：角色被激怒时、被夸奖时、遇到知识盲区时的反应，最能定型。
- 在示例里**演示边界**：比如用户提出越界请求、角色如何婉拒，比只写禁止行为更有效。
- 保持风格正文一致：示例里的说话方式、句长，应当和你想的效果一样，模型会照着学。

## 安全与边界

平台对 AI 的每次输出都有外部安全审查。设计角色时避免诱导违法、暴力、仇恨、露骨色情、自伤鼓励等内容——不是「试试能不能过审」，而是这类内容本身会被拦截，导致对话中断。

如果你的角色会聊到沉重话题（心理压力、伤病等），在禁止行为里写清处理方式：保持克制、不给危险操作的具体步骤、必要时建议用户寻求现实中的帮助。写得越具体，角色表现越稳。

## 世界书、正则与表情包

这三个部分内容较多，单独成页：

- **世界书**：角色的背景知识库，按需注入。详见[世界书](/guide/agent/worldbook)。
- **正则**：对消息做过滤和格式化。详见[正则与表情包](/guide/agent/regex-stickers#正则)。
- **角色表情包**：让角色在合适的时机发贴纸。详见[正则与表情包](/guide/agent/regex-stickers#角色表情包)。

## 测试：发布前先自己玩一会儿

编辑页提供「测试」：给测试会话选一个对话风格，直接和草稿聊天。

测试时重点看：

- 语气对不对——最常见的偏差是「说着说着变成另一个人」，通常要回说话方式字段补细节。
- 边界守不守得住——故意试试禁止行为里写过的场景。
- 开场白和示例对话的实际效果。

草稿测试的会话只有你自己可见。改设定 → 测 → 再改，循环到满意为止。

## 发布与审核

发布流程：

1. 创建并编辑角色（此时为**草稿**）。
2. 用「测试」试玩。
3. 提交审核。广场上显示的是**已发布版本**，草稿里的新改动不会影响广场，直到你发布新版本。
4. 审核通过后其他人就能使用了。

审核状态会标在作品上：「审核中」等待处理；「未通过」会给出外审反馈的分类和原因，修改后重新提交即可。

发布前确认你至少有一份**已发布的对话风格**（社区游玩的硬性要求，见[对话风格](/guide/agent/styles)）。

## 版本管理

角色和对话风格都支持版本管理：查看历史版本、对比两个版本的差异、回滚到之前的版本。大胆改，改坏了随时回滚。

## 常见误区速查

- 把行为约束写进简介 → 模型看不到，应写进人设。
- 大段世界观塞进人设 → 占窗口又难维护，拆进世界书按需注入。
- 开场白里塞设定 → 开场白是场景示范，设定归设定。
- 示例对话写成流水账 → 挑典型场景，尤其要演示边界。
- 参考图随手糊几张 → 生图模型的形象依据，选清晰完整的。
